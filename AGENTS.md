# Agent Working Guide & Development for PicoClaw

## Codebase Map
See `CODEBASE-MAP.md` for the full codebase context map (generated by mapping-codebase skill).

## Core Responsibilities
- Maintain the ultra-lightweight nature of the project (<10MB RAM).
- Ensure cross-platform compatibility (x86, ARM, RISC-V).
- Optimize for performance on low-resource hardware.

## Build & Test
- `make build` - Build the project
- `make test` - Run tests
- `make deps` - Install dependencies

## Project Structure
- `cmd/picoclaw/` - CLI entry point
- `pkg/` - Core logic packages
- `workspace/` - Default agent workspace

## Key Files for Agents
- `pkg/agent/loop.go` - Main processing logic.
- `pkg/tools/` - Extension point for new capabilities.
- `pkg/channels/` - Communication interface implementations.

## Memory & State
- Agent memory is stored in `workspace/memory/MEMORY.md`.
- Session history is kept in `workspace/sessions/`.
- System state is managed via `pkg/state/`.

## Style Guide
- Use standard Go formatting (`gofmt`)
- Follow effective Go patterns
- Document public interfaces

## Workflow Discipline
- When implementing a user-requested behavior change, record the rule/expectation in `AGENTS.md` in the same session.
- Keep Telegram command behavior and docs aligned (`/help`, command registration, and README command list).

- 2026-02-20: Prefer `Makefile` targets as the primary way to build/test/run project tasks.
- 2026-02-20: Do not run tests via direct `go test`; always execute tests through `make` targets (e.g., `make test`, optionally with `TEST`/`RUN` variables).
- 2026-02-20: Before any deletion, agent must inspect path and content provenance first; ask user only when uncertain whether it is safe disposable clutter.
- 2026-02-20: Subagent completion must never be "silent"; max-iteration exhaustion is an error and empty final content must use explicit fallback text.
- 2026-02-20: Named-agent memory writes must only target canonical `.../agents/<name>/memory`; block mirrored `.picoclaw/workspace/agents/...` paths inside project directories.
- 2026-02-20: `./picoclaw/nanobotnb` is read-only downloaded state; never edit files there.
- 2026-02-20: Startup preflight skill-lint issues are warning-only; on gateway start inject warning summary into `idle` session for autonomous cleanup.
- 2026-02-20: Priority controls are channel-agnostic via configurable prefix (`ingress.concat_prefix`, first rune): `<prefix>status` returns immediate runtime status, `<prefix>inject` bypasses queue when no active run exists, `<prefix>first` enqueues at queue head, `<prefix>kill` cancels subagent task; `<prefix><prefix>MESSAGE` appends to previous queued message in same session and must return explicit append confirmation.
- 2026-02-20: Validation and release updates must match change scope: runtime/code-path changes require relevant fmt/lint/tests plus docs/changelog/version in the same pass; docs-only or operational-chore edits do not require full build/test cycle or version bump.
- 2026-02-20: User may edit `TODO.md` during implementation; treat those edits as intentional collaborative updates and continue without escalation.
- 2026-02-20: Parallel user edits are expected; do not stop on unrelated concurrent changes. Pause only for direct conflicts in files being edited or before destructive actions.
- 2026-02-20: Completed items that are already recorded in `CHANGELOG.md` and committed must be removed from `TODO.md` (do not keep checked done items there).
- 2026-02-20: If user intent or requirements are ambiguous, confirm implementation direction before making code edits.
- 2026-02-20: Use native edit tools directly for patches (`apply_patch` tool), not shell-wrapped patch flows.
- 2026-02-20: Changelog entries for behavior changes must explicitly enumerate new user-visible fields/metadata.
- 2026-02-20: Run `make vet` early after structural/API edits, not only at final verification pass.
- 2026-02-20: Respect explicitly requested documentation location; do not add parallel doc edits elsewhere unless requested.
- 2026-02-20: For live-runtime incident diagnosis in this repo, first use skill-based history/log workflow and project-local log paths under `picoclaw/nanobotnb/.picoclaw/workspace/logs/*`; do not assume Docker access unless explicitly confirmed.
- 2026-02-20: File access hard-blocks must be configurable via `agents.defaults.deny_path_patterns` and enforced even when `restrict_to_workspace` is disabled.
- 2026-02-20: Channel-agnostic prefix controls must be fully intercepted (never forwarded to agent): `<prefix>help|status|models|channels|inject|first|kill|delete` and `<prefix><prefix>MESSAGE` append.

- 2026-02-20: Dashboard UX defaults must be live-first: SSE-driven auto updates, manual refresh controls hidden while SSE is connected (visible only as fallback), newest subagents first, and session history auto-scrolled to latest entries.

- 2026-02-20: Active-run urgent inject must preempt (cancel) current session run so queued urgent content is processed next turn; debug logs must not dump full `messages_json/tools_json` payloads.
- 2026-02-20: Subagent completion events from `system` channel must always be delivered into the origin session context (inject when active, otherwise buffered as `system` history), never dropped via outbound `system` routing.
