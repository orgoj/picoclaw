## Mistakes & Corrections (CRITICAL)
### Where I Made Errors:
- I initially reported a tiny binary delta (`+19,580 B`) that was based on a near-term local comparison, not the upstream baseline the user meant.
- I started background/long comparison builds while the user was actively typing, which interrupted flow and annoyed the user.
- I over-explained comparison mechanics before confirming the exact reference baseline in one step.

### What Caused the Mistakes:
- Ambiguous baseline interpretation (local previous build vs upstream/original build).
- Prioritizing “complete measurement” over user interaction pacing constraints.
- Insufficiently strict gating before running long operations during active conversation.

## Lessons Learned
### Technical:
- For size comparisons, always state and lock the reference first:
  - current production binary
  - explicit baseline commit/binary
  - exact bytes + percentage
- Dashboard reliability benefits from combined fixes:
  - server SSE keepalive + anti-buffering
  - client reconnect fallback
  - no-cache headers for static dashboard assets

### Process:
- When user is actively typing rapid feedback, avoid launching long commands unless explicitly requested at that moment.
- Provide answer-first numbers, then method details only if asked.
- Keep production-centric framing (final binary and practical deployability on low-cost Linux SBCs).
